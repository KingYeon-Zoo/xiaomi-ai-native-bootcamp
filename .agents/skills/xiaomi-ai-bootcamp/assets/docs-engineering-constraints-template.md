# 项目工程约束

> 输出位置固定为 `docs/engineering-constraints.md`。必须用项目事实替换全部 `【填写…】`，不得保留模板占位符。

## 1. 项目身份

- 项目名称：`【填写】`
- 项目类型：`【个人项目 / 团队项目】`
- 业务角色：`【填写】`
- 时间限制：`【填写】`
- 核心目标：`【填写一条可验证目标】`
- 当前阶段：`【诊断 / Spec / Design / 实现 / 验证 / 提交】`

## 2. 文档目录规范

- 所有开发过程文件使用 Markdown，统一写入本项目 `docs/` 或其子目录。
- 根目录只保留 `README.md`、`AGENTS.md`，以及课程明确要求时的 `CLAUDE.md`。
- `AGENTS.md`/`CLAUDE.md` 只路由到本文件，不复制工程约束正文。
- 源码、测试代码、数据、配置和可执行原型按项目结构放置，不混入 `docs/`。

## 3. 权威资料优先级

1. `【任务原文或评分标准路径】`
2. `【数据或接口说明路径】`
3. `【docs/spec.md 或 docs/prd.md】`
4. `【docs/design.md】`
5. 当前代码、测试和执行结果

发生冲突时，以更具体、更新、可验证的资料为准，并在 `【docs/ai-log.md 或 docs/decision/ 路径】` 记录冲突与人工判断。

## 4. 目标与非目标

### 目标

- `【可验证目标 1】`
- `【可验证目标 2】`

### 非目标

- `【两天内明确不做的事项 1，以及理由】`
- `【两天内明确不做的事项 2，以及理由】`
- `【用于阻止 AI 过度设计的边界 3】`

详细范围以 `【docs/spec.md 或 docs/prd.md】` 为准。

## 5. 阶段门禁

1. 未读取任务和评分标准，不得提出实现方案。
2. 未完成目标、非目标、验收和边界，不得写业务代码。
3. 未记录方案比较和人工选择，不得确定技术路线。
4. 未写任务验证方式，不得开始该任务。
5. 未执行测试，不得把结果写成 PASS。
6. 存在 BLOCKED 时，不得宣布完成或可提交。

## 6. 允许与禁止

### 允许

- 在 `【允许修改的目录】` 内完成 Spec 覆盖的最小实现。
- 为验收标准增加必要测试、Markdown 文档和证据。
- 在有验证证据时调整 Design，并同步记录原因。

### 禁止

- 修改 `【只读数据或原始要求路径】`。
- 把过程 Markdown 写在 `docs/` 外。
- 增加不在 Spec 中的登录、数据库、复杂框架或无关功能。
- 为了让测试通过而降低验收标准或改写预期结果。
- 伪造测试、会议、提交、人工反馈或 AI 判断。
- 进行与当前任务无关的重构。

## 10. AI 协作记录

关键 AI 协作必须写入 `【docs/ai-log.md 或 docs/ai/ai-collaboration-log.md】`，每条包含：目的、输入、建议、人工判断、验证。重点记录范围收窄、方案比较、反证、风险、失败修复、测试设计和 Review；不得只写“采纳”或复制聊天截图。

## 11. 失败处理

- 命令失败：保留错误输出，定位根因后最小修复并回归。
- 资料冲突：停止实现，记录冲突并由 `【个人负责人 / 团队决策人】` 判断。
- 测试失败：状态记为 BLOCKED，不删除失败用例。
- Demo 失败：使用 `【docs/prototype/ 中的截图/录屏说明路径】`，同时说明实时链路失败原因。

## 12. 团队规则

个人项目填写“不适用”。团队项目填写：

- 最终范围决策人：`【填写】`
- 模块负责人及备份：`docs/collaboration/role-division.md`
- 会议与决策记录：`docs/collaboration/`
- Issue 与阻塞记录：`docs/collaboration/issue-log.md`
- 合并前 Review：代码、文档、测试必须由非作者复核并记录到 `docs/validation/review-record.md`。

## 13. 完成定义

- **PASS**：必需文件存在且非空；过程 Markdown 全部位于 `docs/`；无占位符；README 命令可复现；验收与测试一一映射；AI 日志有人工判断。
- **WARNING**：主要产物存在，但内容、命令、映射、边界或 Review 不充分。
- **BLOCKED**：过程 Markdown 位于 `docs/` 外；关键文件缺失；命令不可复现；测试失败；存在模板占位符或结果真实性风险。

交付前必须运行 `【专用检查器】` 和 `.agents/skills/xiaomi-ai-bootcamp/scripts/audit-xiaomi-project.sh`。

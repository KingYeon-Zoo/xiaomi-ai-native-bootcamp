# Day 1 个人复盘

## 今天最大的认知变化

我最明显的变化是把“文件存在”与“证据可复核”区分开。原提交虽然有六份文档，但 README 指向的源码和测试并未包含在提交仓库，评审者无法执行命令。这次没有通过增加描述掩盖缺口，而是补回课程检查器要求的 `rag-assistant/` 与 `bug-fix-lab/`，并把验收标准映射到真实命令和实际结果。

## 今天最困难的地方

最困难的是处理课程旧路径与当前 `docs/` 规范冲突。若直接把正文留在根目录，过程文档会继续散落；若只迁入 `docs/`，课程检查器又会判缺失。我选择以 `docs/` 为唯一正文，用符号链接保留检查器所需入口。这个决定避免内容重复和后续失真，同时让两套规则都能被验证。

## 一个具体的人工取舍

RAG 实现可选择向量数据库和真实模型，也可选择关键词检索与本地 Mock。AI 更容易建议前者，因为展示效果更丰富；我拒绝该扩展。Day 1 的验收对象是切片、检索、Prompt、引用、拒答和证据链，外部服务会引入密钥和网络风险。13 条离线行为测试足以验证本次范围，向量检索留作后续评测，不伪装成已完成。

## 如果再做一次

我会在写实现前先建立固定评测集，把正确匹配、跨段落、资料外、混淆、空输入、超长输入和纯停用词全部写入验收映射。这样检索策略的每次调整都能用同一组输入比较，而不是依赖“看起来相关”的主观判断。

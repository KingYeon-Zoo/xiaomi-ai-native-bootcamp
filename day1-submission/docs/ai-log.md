# Day 1 AI 协作决策记录

每条记录包含目的、输入、建议、人工判断、验证；这里只保留影响范围、设计、修复和提交质量的关键协作。

## 第 1 条：样例提交评级

| 字段 | 内容 |
|---|---|
| 目的 | 判断只有代码、只有 README、完整证据三类提交的状态。 |
| 输入 | Day 1 样例包、六类文件定义和评审模板。 |
| 建议 | AI 初步把只有 README 的样例也判为 BLOCKED。 |
| 人工判断 | 修改为 WARNING；README 提供最低限度说明，但缺少 Spec、Design、测试和 AI 判断，证据不足但并非完全不可读。 |
| 验证 | 对照课程样例最终标注：only-code 为 BLOCKED、readme-only 为 WARNING、full-evidence 为 PASS。 |

## 第 2 条：Bug 最小修复范围

| 字段 | 内容 |
|---|---|
| 目的 | 修复字符串优先级和空标题，同时避免无关扩展。 |
| 输入 | 修复前失败记录、`task_manager.py`、每个 Bug 最小修改约束。 |
| 建议 | AI 除类型转换和非空校验外，还建议标题长度、字符白名单和 HTML 转义。 |
| 人工判断 | 只采纳整数转换、别名映射和非空校验；拒绝其余建议，因为没有复现证据且会扩大课程范围。 |
| 验证 | `python3 bug-fix-lab/test.py` 的 7 条正常、边界和回归断言全部通过。 |

## 第 3 条：RAG 范围收窄

| 字段 | 内容 |
|---|---|
| 目的 | 把“做一个 RAG 助手”转成 Day 1 可验收 MVP。 |
| 输入 | 固定 FAQ、六环节数据流要求、一天课程时间。 |
| 建议 | AI 建议加入向量库、上传、Web UI、登录和历史记录。 |
| 人工判断 | 全部拒绝；本次只保留固定 FAQ、CLI、关键词检索、Mock 回答、引用和拒答。 |
| 验证 | `docs/spec.md` 有 4 项目标、5 项非目标、6 条可执行验收标准。 |

## 第 4 条：接口边界

| 字段 | 内容 |
|---|---|
| 目的 | 固定切片、检索、回答和 CLI 的职责，避免模块互相越界。 |
| 输入 | FAQ 格式、源码骨架和 Mock OpenAI 兼容接口。 |
| 建议 | AI 建议让 `answer()` 自己读取 FAQ，减少调用参数。 |
| 人工判断 | 拒绝；`answer()` 只消费检索结果，FAQ 加载和零命中拒答由入口负责，便于单独测试每层。 |
| 验证 | `test_basic.py` 验证接口结构，`test_rag.py` 验证端到端来源与拒答。 |

## 第 5 条：检索方案选择

| 字段 | 内容 |
|---|---|
| 目的 | 在关键词方案与向量方案之间选择可复现实现。 |
| 输入 | 约 10 条课程 FAQ、无第三方依赖要求、资料外拒答用例。 |
| 建议 | AI 推荐 Embedding 与向量数据库以提升语义召回。 |
| 人工判断 | 拒绝外部依赖，采用同义词替换、停用词拆分、关键词命中和距离加分；固定数据规模下更易解释和验证。 |
| 验证 | 13 条用例覆盖正确匹配、跨段落、资料外、混淆与边界，全部通过。 |

## 第 6 条：真实模型与 Mock 的取舍

| 字段 | 内容 |
|---|---|
| 目的 | 选择回答模块的模型依赖。 |
| 输入 | 课程关注 RAG 链路，评审环境不保证密钥、网络或额度。 |
| 建议 | AI 建议接真实 API，让回答更自然。 |

## 第 7 条：失败记录处理

| 字段 | 内容 |
|---|---|
| 目的 | 决定最终全绿后是否保留修复前失败。 |
| 输入 | Bug 修复前两个失败、最终 7 条回归通过。 |
| 建议 | AI 建议只展示最终 PASS，使文档更简洁。 |
| 人工判断 | 拒绝；保留修复前输入、预期和实际，但明确其为课堂历史证据，不伪装成 2026-07-15 重新执行。 |
| 验证 | `docs/bugs/reproduction.md` 与 `docs/bugs/fix-record.md` 分别记录前后状态。 |

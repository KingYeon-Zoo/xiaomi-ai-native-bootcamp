# Day4 跨项目设计与决策索引

## 总体数据流

```text
Apache.tar.gz -> 严格行解析 -> 结构化 CSV -> 三类筛选 -> 统一统计 -> 图表/报告

6 个邮件 tar.bz2 -> MIME 解析 -> raw/cleaned 双轨 -> 固定分层切分
                                         |-> 六特征规则 --------|
                                         |-> train-only NB fit -|-> 同测试集指标/图/FP-FN

两项目初版 -> 三维审查 -> 固定反例 -> 只修模块 Error 率 -> 全量回归/Git 范围检查
```

## 关键设计选择

| 决策 | 选择 | 拒绝项与理由 |
|---|---|---|
| P1 解析 | 结构正则、时间校验、语义字段分开 | 单个巨型正则会把普通数字误当 error_code，失败原因难定位 |
| P1 统计 | 统计表作为图表与报告唯一数据源 | 各图内部重复 groupby 会造成口径漂移 |
| P2 数据加载 | 直接读取 tar member 并保留 source | 解压到同一目录可能覆盖同名 ham/spam 目录 |
| P2 特征 | raw 与 cleaned 同时进入特征接口 | 只传 cleaned 会让大写、标点和货币特征恒为零 |
| P2 实验 | 先分层切分，只在 train fit Vectorizer | 完整数据 fit 会泄漏测试词表；最终测试集不能用于循环调参 |
| P3 修改 | 两次 groupby + 按 module merge | 重写整个统计层或引入新框架超出一个问题的范围 |

## 文档路由设计

课程最终清单要求项目根目录固定文件名，训练营 Skill 要求过程正文只在 `docs/`。正文因此位于 `docs/project1/`、`docs/project2/` 和 `docs/agent-review-report.md`；题目位置用相对符号链接暴露同名入口。主流程写入 `projectN/analysis_report.md` 时会跟随链接更新 docs 正文，避免两份报告不一致。

## 失败与边界

- P1 非标准续行只计 invalid，不在没有规则时猜测归并关系。
- P2 单封 MIME 异常保留样本与告警；空文本不删除、不改标签。
- 缺少压缩包、有效数据为空、模型未 fit 均明确失败。
- 图表字体优先使用系统中文字体；没有候选字体时仍生成图并由验收记录告警。

详细模块、接口、任务和风险见两个项目的 `spec.md` 唯一正文。

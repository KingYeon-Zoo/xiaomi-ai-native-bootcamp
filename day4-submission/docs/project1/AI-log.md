# Project 1 AI 协作日志

## Session 1：解析字段与错误码边界

| 字段 | 内容 |
|---|---|
| 目的 | 确认五字段提取，避免普通数字污染 error_code |
| 输入 | Apache 示例行、题目“仅提取 error state N”规则 |
| AI 建议 | 用一个正则同时捕获时间、级别、模块与任意数字 |
| 人工判断 | 修改：结构正则只切三段；时间单独校验；模块按词表；error_code 只用专用正则。复杂正则更短，但会把 PID/端口误识别 |
| 验证 | `test_parser_does_not_treat_unrelated_number_as_error_code` 与全量 error_code 范围检查 |

## Session 2：筛选与统计口径

| 字段 | 内容 |
|---|---|
| 目的 | 决定三类筛选和模块 Error 率公式 |
| 输入 | Lesson 2 要求及模块 Error 率明确定义 |
| AI 建议 | 先取全部 error，再对关键词和 error state 继续过滤；模块比例除以全部 Error |
| 人工判断 | 三个 CSV 应是三种独立观察窗口，不能默认嵌套；模块 Error 率必须以模块全部日志为分母。初版实现仍错误使用全部 Error，已列为 Project 3 首要候选 |
| 验证 | 固定三行数据：修改前错误得到 LDAP=0.5、mod_jk=0.5；修改后得到 LDAP=1.0、mod_jk=0.5；定向测试 2 PASS |

## Session 3：图表与报告可信度

| 字段 | 内容 |
|---|---|
| 目的 | 避免图表、CSV、报告各自计算导致口径漂移 |
| 输入 | 三张必交图、报告必须来自实际输出的规则 |
| AI 建议 | 每个绘图函数直接接收明细并内部 groupby |
| 人工判断 | 拒绝重复聚合；统计函数产出唯一中间表，绘图与报告都消费它。这样统计单测可以覆盖图表数字来源 |
| 验证 | 全量生成 52,004 条结构化记录、3 张可读图；独立复算 error=38,081、error state=4,349、workerEnv Error 率=43.24% |

# Day4 AI 协作决策总账

## 记录 1：最终目录与 Demo 冲突

| 字段 | 内容 |
|---|---|
| 目的 | 决定采用 Demo 目录还是 Day4 data 的最终目录 |
| 输入 | `day4-data/README.md`、两份评分标准、Demo 两个检查器 |
| AI 建议 | Demo 可作为代码接口参考，但其 `output/`、`docs/prd.md`、`src/test_*.py` 等结构已过时 |
| 人工判断 | 接受冲突判断，选择最新且更具体的 data 要求；拒绝机械复制 Demo，并保留题目规定的根目录文件名 |
| 验证 | 逐项对照最终目录树；最终运行自建清单检查，不使用旧检查器作为唯一验收 |

## 记录 2：原始数据是否进入 Git

| 字段 | 内容 |
|---|---|
| 目的 | 在可复现与仓库体积之间做取舍 |
| 输入 | 最终清单不含原始语料；P1/P2 都要求派生 CSV；原始压缩包位于只读 `day4-data` |
| AI 建议 | 将原始压缩包复制进提交可实现完全自包含 |
| 人工判断 | 拒绝。题目明确不应自行新增必交文件，原始数据有公开来源且体积大；提交可复核派生输出，README 要求用户用参数指向课程数据 |
| 验证 | `.gitignore` 排除原始数据；两个 `main.py` 都提供明确数据参数和缺失错误信息 |

## 记录 3：邮件数据读取方式

| 字段 | 内容 |
|---|---|
| 目的 | 安全处理六个包含同名目录的压缩包 |
| 输入 | 两批 spam 与 ham 包解压后目录名可能相同；总样本应为 7,449 |
| AI 建议 | 按 README 循环解压到同一 data 目录 |
| 人工判断 | 修改建议：直接遍历 tar member，标签由压缩包名决定，避免覆盖、路径污染和额外磁盘副本 |
| 验证 | 全量运行后检查总数、类别数和 `source` 列；单封解析失败记录告警但不改标签 |

## 记录 4：Task 3 候选优先级

| 字段 | 内容 |
|---|---|
| 目的 | 从真实行为风险而非代码风格中选择一个修改 |
| 输入 | P1 初版模块统计、题目对模块 Error 率的明确定义、P2 raw/cleaned 与 fit 边界 |
| AI 建议 | 可整理命名、拆分函数或增加类型注解 |
| 人工判断 | 拒绝风格项作为核心问题；优先验证 P1 分母是否用“该模块全部日志数”，因为分母错误会直接改变运维排序结论 |
| 验证 | 修改前固定样本复现、修改后定向测试、P1/P2 回归、Git diff 范围检查 |

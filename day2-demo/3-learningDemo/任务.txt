作业要求

提交文件：learning-record.md + Demo + test-record.md
建议补充：AI-log.md（AI 协作记录）

选一个陌生技术，跑通最小可验证 Demo。

文件	必须包含	最低要求
learning-record.md	我知道 / 我不知道 / 如何验证	① learning-record.md：我知道 / 我不知道 / 如何验证三部分都有内容
② “我不知道”至少 2 条，每条是具体的、可验证的问题
Demo	可运行的最小代码	③ Demo 能运行，有运行截图或日志
test-record.md	验证结果（命令 + 期望 + 实际 + PASS/FAIL）	④ test-record.md：至少 2 条验证结果
⑤ 有未解决的疑问和下一步计划

⚠️ 注意
不要只粘贴 AI 的回答。必须有你自己的判断和取舍。
❌ 不通过：全部是 AI 原文，没有人工标注采纳 / 拒绝及原因。


评审 DEMO 的 4 个维度

| 维度           | 评审问题               |
| ------------ | ------------------ |
| 🏃 能运行       | 按 README 能跑通吗？     |
| 📋 README 完整 | 安装步骤、运行命令、依赖说明齐全吗？ |
| 🧱 边界诚实      | 说清楚了支持什么、不支持什么吗？   |
| 🤖 AI 依赖可解释  | AI 帮了什么、人工判断了什么？   |

每个维度都要给出具体证据，不能只写“通过”或“不通过”。


学生练习：评审同桌的 DEMO

任务：评审同桌的自学 DEMO

按 4 个维度检查：能运行、README 完整、边界诚实、AI 依赖可解释。

| 步骤     | 动作                       | 产出               |
| ------ | ------------------------ | ---------------- |
| Step 1 | 按 README 运行同桌的 Demo      | 运行结果             |
| Step 2 | 检查 README 是否完整（缺步骤？缺依赖？） | 具体问题             |
| Step 3 | 问 2 个边界问题（资料外？超时？）       | 边界测试结果           |
| Step 4 | 写证据型反馈 + 给结论             | `peer-review.md` |

⚠️ 注意
每个问题必须有证据：你看到了什么、运行了什么。不要只写感受。

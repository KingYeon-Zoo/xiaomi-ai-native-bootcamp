# PRD — 小红书文案生成器

## 1. 产品定义

**名称**：小红书文案生成器

**一句话描述**：通过终端对话收集产品信息，AI 自动生成小红书风格的种草文案

**用户**：需要写小红书文案的运营 / 个人博主

**技术栈**：Python + LangChain + OpenAI API

## 3. 输入字段设计

| 字段 | 变量名 | 必填 | 说明 | AI 建议备选项 |
|------|--------|------|------|---------------|
| 产品名称 | `product` | ✅ | 要推广的产品 | 小米SU7、iPhone 15、戴森吹风机、元气森林、兰蔻小黑瓶 |
| 目标用户 | `target_user` | ✅ | 产品的目标受众 | 大学生、白领、宝妈、程序员、健身人群、学生党 |
| 风格 | `style` | ❌ | 文案风格 | 种草安利、测评干货、情绪共鸣 |

### 交互规则

1. **必填字段为空时**：提示 "⚠️ 这个是必填项哦～"，重新询问
2. **可选字段为空时**：使用默认值 "（无）"
3. **退出命令**：用户输入 "quit" 或 "exit" 时退出程序

## 4. Prompt 模板

```
你是一个专业的小红书文案写手。请根据以下信息生成一篇小红书笔记。

【产品信息】
- 产品名称: {product}
- 目标用户: {target_user}
- 风格要求: {style}

【输出要求】
请生成以下内容：

1. **标题**（15-20字，带 emoji，吸引眼球）
2. **正文**（300-500字，包含：
   - 开头 hook（引发共鸣或好奇）
   - 产品介绍（自然融入，不要太硬广）
   - 使用体验/卖点展开
   - 结尾号召（引导互动）
3. **标签**（5-8个，#开头，热门+长尾组合）

【风格要求】
- 语气: 亲切、真实、像朋友推荐
- 多用 emoji，但不要过度
- 适当用小红书流行语（姐妹们、绝绝子、真的会谢 等）
- 分段清晰，多用短句
```

## 6. 技术方案

### 组件选型

| 组件 | 选型 | 说明 |
|------|------|------|
| Prompt 模板 | `PromptTemplate` | 动态填充用户输入 |
| LLM | `ChatOpenAI` | 调用 GPT（默认 gpt-3.5-turbo） |
| Chain | `LLMChain` | 串联 Prompt → LLM |
| 信息收集 | 原生 `input()` | while True 循环，不用 Memory |
| 测试框架 | `pytest` | 单元测试 + Mock |

### 代码结构

## 7. 自动测试设计

### 测试用例

| # | 测试项 | 测试方式 | 输入 | 预期结果 |
|---|--------|----------|------|----------|
| 1 | Prompt 模板填充 | 单元测试 | product="测试产品", target_user="测试用户", style="种草" | 模板变量正确替换 |
| 2 | 必填校验 - 空产品 | 单元测试 | product="" | 返回错误提示 |
| 3 | 必填校验 - 空用户 | 单元测试 | target_user="" | 返回错误提示 |
| 4 | 可选字段跳过 | 单元测试 | style="" | 使用默认值 "（无）" |
| 5 | LLM 调用流程 | Mock 测试 | mock LLM 返回 | 验证调用参数正确 |
| 6 | 完整生成流程 | 集成测试 | 模拟用户输入 | 输出包含标题+正文+标签 |

### Mock 策略

- LLM 调用使用 `unittest.mock.patch` mock
- 避免测试时消耗 API 额度
- Mock 返回固定的测试文案

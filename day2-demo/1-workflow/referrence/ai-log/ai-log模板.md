> **关键决策标记**：🔴 拒绝 AI 建议 / 🟡 修改 AI 建议 / 🟢 采纳但有附加条件

## 阶段一：Spec 定义

### 记录 1：确定检索策略 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 确定 RAG 检索模块的实现方式 |
| **输入** | `course-faq.md`（10 条 FAQ）、`questions.json`（测试问题） |
| **建议** | AI 建议两种方案：(1) 纯关键词匹配 + 小同义词表；(2) 引入 embedding 做语义搜索。同时建议同义词表做自动扩展（NLP 推断） |
| **人工判断** | **拒绝方案 2 和自动扩展**。采纳方案 1。理由：项目目的是跑通开发流程，不是做生产级 RAG；10 条 FAQ 规模下关键词匹配足够；embedding 和 NLP 属于过度设计，与 spec 非目标冲突 |
| **验证** | 对照 `questions.json` 的 10 个测试问题，逐一确认关键词能否命中对应 FAQ 编号 |

### 记录 2：确定切片策略 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 确定 `course-faq.md` 的切片粒度 |
| **输入** | `course-faq.md` 的 Markdown 结构（`## [faq-XX]` 标题分隔，内含表格、列表、代码块） |
| **建议** | AI 建议两种方案：(1) 按 `## [faq-XX]` 整条切；(2) 把表格单独切出来做独立 chunk |
| **人工判断** | **拒绝方案 2**。采纳方案 1。理由：每条 FAQ 是完整语义单元，表格脱离标题会丢失上下文（如 faq-02 的表格不知道在说哪 6 个文件）；10 个 chunk 规模下不需要更细粒度 |
| **验证** | 手动检查 10 条 FAQ，确认每条以 `## [faq-XX]` 开头、内容自包含 |

### 记录 3：确定拒答策略 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 确定资料外问题的拒答逻辑 |
| **输入** | `questions.json` 中的"资料外"和"混淆"类测试用例、`mock_server.py` 的已有拒答逻辑 |
| **建议** | AI 建议两种方案：(1) 零命中拒答；(2) 分数阈值拒答（最高分 < 阈值则拒答） |
| **人工判断** | **拒绝方案 2**。采纳方案 1。理由：`mock_server.py` 已有基于关键词白名单的资料外检测，两层阈值会冲突；10 条 FAQ 的关键词区分度足够高；方案 2 的阈值调参在当前规模下没有实际收益 |
| **验证** | 用"奖学金政策是什么？"和"今天中午吃什么？"测试，确认零命中时输出拒答信息 |

### 记录 4：确定 LLM 后端 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 确定调用真实 LLM API 还是 mock 服务 |

### 记录 6：确定切片归属 🟢

| 字段 | 内容 |

| **目的** | 确定切片逻辑放在哪个组件 |

| **建议** | AI 建议两种方案：(1) 切片放 retrieve.py 内部；(2) main.py 先切片再传给 retrieve |

## 阶段四：实现与调试

### 记录 12：中文分词策略（实现中决策）🔴

| 字段 | 内容 |
|------|------|
| **目的** | 解决 retrieve.py 的中文分词粒度问题 |
| **输入** | 测试用例 "Day1要交什么？" 无法正确匹配 faq-02 |
| **建议** | AI 尝试了 3 种方案：(1) 单字拆分；(2) 整句不拆分；(3) 2-gram 重叠 |
| **人工判断** | **拒绝全部 3 种方案**。最终采用自定义方案：先按停用词拆分（"什么"拆开 "Day1提交什么"），再按字符类型边界拆分（英文 vs 中文），得到 ["Day1", "提交"]。理由：单字噪声太大、整句无法匹配子串、2-gram 产生垃圾 token |
| **验证** | 7 个 retrieve 验证用例全部通过 ✅ |

### 记录 13：评分策略（实现中决策）🔴

| 字段 | 内容 |
|------|------|
| **目的** | 解决 "Day1要交什么？" 时 faq-01/02/06 分数相同的问题 |
| **输入** | retrieve 返回 faq-01/02/06 均为 score=2（"Day1"和"提交"都命中） |
| **建议** | AI 建议两种方案：(1) 标题加权（title x2）；(2) 共现加权（命中 2+ 词 +1） |
| **人工判断** | **拒绝两种方案**。方案 1 导致 faq-06 赢（"Day1"在标题），方案 2 三个 chunk 仍然平分。最终采用 proximity 加权——关键词在文本中距离越近加分越多。理由：用户问的是"交什么"，faq-02 中 "Day1" 和 "提交" 距离最近（"Day1 最终提交包"） |
| **验证** | "Day1要交什么？" → faq-02 排第一 ✅ |

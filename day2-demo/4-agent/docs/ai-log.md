## 阶段三：实施与调试

### 记录 8：RAG 分词策略 — 逐字拆分方案失败 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 实现 RAG 检索工具的中文分词逻辑 |
| **输入** | agent-design.md 中定义的 RAG 工具（关键词匹配，最简实现） |
| **建议** | AI 建议最简方案：中文逐字拆分，英文按词拆分，子串包含匹配 |
| **人工判断** | **拒绝该方案**。理由：逐字拆分导致单字 token（如"交""什""么"）几乎匹配所有 chunk，"Day1要交什么？" 返回所有 10 条 FAQ 同分，无法区分；"奖学金政策"的单字也会误命中其他 chunk |
| **验证** | pytest 2 个 RAG 测试失败：test_normal_query（sources 为空）和 test_has_source（无来源编号） |

### 记录 9：RAG 分词策略 — 2-gram 方案失败 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 改进分词粒度，减少单字噪声 |
| **输入** | 记录 8 失败原因（单字 token 太泛） |
| **建议** | AI 建议改用中文 2-gram（bigram）：连续中文字符每 2 个一组，如"提交"→"提交"，"奖学金"→"奖学""学金" |
| **人工判断** | **拒绝该方案**。理由：2-gram 仍有误匹配——"奖学金"拆成"奖学""学金"，其中"学金"碰巧在其他 chunk 中出现（如"学习"拆出"学习"），导致"奖学金政策"仍然命中多个 chunk，无法做到零命中拒答 |
| **验证** | 测试"奖学金政策是什么？"仍返回多个匹配结果，未实现拒答 |

### 记录 11：停用词表修正 🔴

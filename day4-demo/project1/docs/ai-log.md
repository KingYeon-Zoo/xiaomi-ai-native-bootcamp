## 阶段一：PRD 需求讨论

### 1. 数据规模确认 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 确认数据规模和处理性能 |
| **输入** | 作业说"约 2000 条"，实际 Apache.log 有 56,482 行 |
| **建议** | AI 建议按作业描述的 2000 条处理 |
| **人工判断** | **拒绝**，以真实数据为准。理由：作业描述有误；经性能测试 5 万行解析仅需 0.038 秒 |
| **验证** | PRD 数据规模已更新为 56,482 行 ✅ |

### 2. 格式异常行处理 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 确定 4,478 行格式异常日志的处理方式 |
| **输入** | 4,478 行仅有 `script not found or unable to stat`，无时间戳 |
| **建议** | AI 建议尝试修复或补充这些行的数据 |
| **人工判断** | **拒绝**。理由：缺少字段无法结构化，强行补充是伪造数据 |
| **验证** | PRD 非目标已明确"不处理格式异常行" ✅ |

### 3. 非功能性需求范围 🔴

| 字段 | 内容 |
|------|------|
| **目的** | 确定可复用性、可扩展性等需求范围 |
| **输入** | 项目约束（3 课时 / 约 3 小时） |
| **建议** | AI 提出做通用日志框架、支持多日志格式、实时监控 |
| **人工判断** | **全部拒绝**。理由：3 小时硬约束，聚焦当前任务，不做过度设计 |
| **验证** | PRD 非目标列出 8 项不做内容 ✅ |

### 4. 目标与非目标细化 🟡

| 字段 | 内容 |
|------|------|
| **目的** | 明确项目的可衡量目标 |
| **输入** | 真实数据情况（56,482 行、52,004 可解析、12 种错误类型） |
| **建议** | AI 提供初步目标列表 |
| **人工判断** | **修改为可衡量标准**：CSV = 52,004 行、至少 12 种错误类型、3 张图表、8 章节报告 |
| **验证** | PRD 目标已更新 ✅ |

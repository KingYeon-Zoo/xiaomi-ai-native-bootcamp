# Spec — RAG 课程助手

## 目标（Goals）

1. 用户通过 CLI 输入 Day1 训练营相关问题，系统输出基于 `course-faq.md` 的回答，回答末尾注明来源编号（如 `[faq-02]`）
2. 检索模块基于关键词匹配实现，从 `course-faq.md` 按 `## [faq-XX]` 切片为 10 个 chunk，对用户问题做关键词命中评分，返回 top 3
3. 对于与课程资料完全无关的问题（关键词零命中），系统拒绝回答并输出"资料中没有找到依据"
4. 使用 `llm-mock/mock_server.py` 作为 LLM 后端，兼容 OpenAI Chat Completions API 格式
5. 空输入时在 CLI 入口层直接提示"请输入您的问题"，不进入检索流程
6. 超长输入（超过 200 字符）时在 CLI 入口层截断至 200 字符并继续处理

## 非目标（Non-Goals）

1. **不做 Web UI** — 仅支持命令行调用，不提供浏览器界面
2. **不接真实 LLM API** — 本项目聚焦开发流程演示，使用 mock 服务即可
3. **不做向量检索 / 语义搜索** — 不引入 embedding 模型或向量数据库，仅用关键词匹配
4. **不支持 course-faq.md 以外的数据源** — 知识库固定为这 10 条 FAQ
5. **不做同义词自动扩展** — 同义词处理仅通过手动维护的小映射表实现，不做 NLP 自动推断

## 验收标准（Acceptance Criteria）

1. **正确匹配**：输入 `"Day1要交什么？"`，输出包含 6 类证据文件的描述，且来源注明 `[faq-02]`
2. **正确匹配**：输入 `"什么是可复核交付？"`，输出包含"助教""独立判断""证据"等关键词，来源注明 `[faq-01]`
3. **跨段落**：输入 `"Spec中的非目标和AI过度设计有什么关系？"`，输出至少引用 `[faq-04]` 或 `[faq-10]` 其中之一
4. **资料外拒答**：输入 `"奖学金政策是什么？"`，输出包含"资料中没有找到依据"
5. **空输入**：输入空字符串，输出"请输入您的问题"
6. **来源引用**：所有非拒答回答的末尾必须包含至少一个 `[faq-XX]` 编号
7. **超长输入**：输入超过 200 字符的字符串，系统截断至 200 字符后正常处理，不报错
8. **测试通过**：运行 `python3 tests/test_basic.py` 全部检查项通过

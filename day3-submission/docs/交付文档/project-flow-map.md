## 五棒接力明细

### 第一棒：产品

**文件**：product-prd.md
**入**：多人旅行共同支出记账的痛点
**出**：验收「创建旅行→添加成员→添加账单→结算」核心闭环
**关键产出**：
- 用户画像：旅行参与者（记账人）
- 15 条验收条目：P0×6 + P1×6 + P2×3
- 非目标 8 条，范围钉死

↓ 交接物：PRD + 验收条目 ↓

---

### 第二棒：设计

**文件**：design-options.md + plan.md
**入**：PRD + P0 验收条目（6 条）+ 核心对象定义
**出**：React+Vite 前端 + Python FastAPI 后端方案
**关键产出**：
- 三方案对比：CLI / Web / 小程序 → 选中 Web
- 技术选型 6 项（前端/样式/API/后端/存储/测试）
- 数据模型、API 端点、结算算法、页面布局

↓ 交接物：选定方案 + 接口定义 + 算法 ↓

---

### 第三棒：研发

**文件**：dev-workflow.md
**入**：选定方案 + 核心对象（旅行/成员/账单）+ 结算算法
**出**：可运行实现（前端页面 + 后端 API + 本地 JSON 存储）
**关键产出**：
- 5 个任务（T1-T5），每个实现+测试一体
- 后端 9 个 API 端点，25 条 pytest 用例
- 前端 2 个页面 + 7 个组件，15 条 vitest 用例

↓ 交接物：可运行版本 + 测试用例 ↓

---

### 第四棒：测试

**文件**：test-strategy.md
**入**：验收条目（P0 六条 + P1 六条 + P2 三条）+ 失败路径用例
**出**：pytest 25 passed + vitest 15 passed + 手动 e2e 通过
**关键产出**：
- 后端 25 条：正常 / 边界 / 失败全覆盖
- 前端 15 条：表单校验 + 渲染 + 回调
- 手动 e2e 10 步：完整主流程验证

↓ 交接物：测试报告 + 上线版本 ↓

---

### 第五棒：运营

**文件**：`docs/reflection.md`
**入**：上线版本 + 复盘回灌产品
**出**：个人取舍、失败复测、残留风险与下一步

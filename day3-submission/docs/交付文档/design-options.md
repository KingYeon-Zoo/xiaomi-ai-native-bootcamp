# TripSplit · 方案取舍

> 三方案本质不同、每个都有风险列、选择与不选都有理由。

---

## 方案对比

| 方案 | 优势 | 风险 | 结论 |
|------|------|------|------|
| A CLI | 最快最稳 / 零依赖 | 展示弱 / 非技术用户难用 | 备选 |
| B Web 前后端 | 展示强 / 体验好 / 跨平台 | 需前后端联调 / 部署复杂 | 选中 ✓ |
| C 微信小程序 | 贴近真实使用场景 | 微信审核周期 / 两天难收口 | 保留入口 |

---

## 最终选择：B Web 前后端

- React + Vite 前端 + Python FastAPI 后端
- 本地 JSON 文件存储（`data/trips.json`）
- 两天可交付 + 跨平台访问 + 联调风险可控

---

## 为什么不选 A / C

### A：CLI 命令行

- 答辩展示太弱，无法直观呈现 UI 交互
- 非技术用户无法使用，不符合"记账人录入后发群里"的场景
- 纯文本输出结算结果，复制到微信格式不友好

### C：微信小程序

- 需要企业主体或个人认证，审核周期不可控
- 与微信支付生态绑定过深，PRD 明确"不做真实支付"
- 两天时间窗口内集成风险高，难以收口

---

## 技术选型明细

| 层 | 选型 | 理由 |
|----|------|------|
| 前端框架 | React 18 + Vite | 组件化开发快 / HMR 热更新 / 社区成熟 |
| 样式方案 | Plain CSS | 零配置 / 最轻量 / 符合 3 天节奏 |
| API 调用 | 原生 fetch | 零依赖 / 浏览器原生支持 |
| 后端框架 | Python FastAPI | 异步性能好 / 自动文档 / 上手快 |
| 数据存储 | 本地 JSON 文件 | 无需数据库 / 部署简单 / 满足单机场景 |
| 测试框架 | pytest + vitest | Python 生态标配 / 前端 vitest 集成 Vite |

---

## 交互主路径

```
旅行列表 → 创建旅行 → 添加成员（≥2） → 添加账单 → 持续录入 → 点击结算 → 查看结果
```

## 失败路径

| 场景 | 处理 |
|------|------|
| 金额 ≤ 0 | 校验拒绝，提示"金额必须大于 0" |
| 成员名为空/重复 | 校验拒绝，明确错误提示 |
| 参与人未选 | 校验拒绝，提示"至少选择一个参与人" |
| 结算时账单为空 | 提示"请先添加账单" |
| 资源不存在 | 返回 404 + 具体错误信息 |

---

## 存储方案考量

选择本地 JSON 文件而非数据库的理由：
1. PRD 明确"不做云端同步 / 多人实时协作"
2. 单用户单机场景，无需并发控制
3. 部署零依赖，开发调试方便
4. 数据量小（单次旅行几十条账单），JSON 性能足够

风险：JSON 文件并发写入可能丢数据 → 单机场景可接受

---

## 结算算法方案

| 方案 | 优势 | 风险 | 结论 |
|------|------|------|------|
| 贪心匹配 | 实现简单 / 转账次数近似最优 | 非精确最优解 | 选中 ✓ |
| 精确最优 | 转账次数最少 | NP-hard / 实现复杂 | 放弃 |

选择贪心的理由：旅行 AA 场景人数 2-8 人，贪心完全够用，不需要过度设计。

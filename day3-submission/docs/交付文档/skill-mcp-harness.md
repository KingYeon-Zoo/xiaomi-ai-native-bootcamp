# TripSplit · 自动化三件套

> Skill = 怎么做、MCP = 接什么、Harness = 自动跑。各管一段，组合成自动化运营。

---

## Skill = 怎么做

### 已沉淀的 Skill

| Skill | 用途 | 输入 | 输出 |
|-------|------|------|------|
| 创建旅行 | 初始化账本 | 名称 + 日期 | trip 对象 |
| 添加成员 | 管理参与者 | 成员名 | members 列表 |
| 添加账单 | 记录支出 | 名称/金额/付款人/参与人/分类/日期 | expense 对象 |
| 生成结算 | 计算分摊 | trip id | settlement 结果 |
| 结算算法 | 贪心匹配 | expenses + members | transfers 方案 |

### Skill 可复用性

- 结算算法（settle.py）独立封装，可被任何 Python 项目复用
- API 接口遵循 RESTful 规范，可被任何 HTTP 客户端调用
- 前端组件（ExpenseForm / Settlement）可抽为独立 npm 包

### 扩展方向

| 方向 | 改动 | 复杂度 |
|------|------|--------|
| 多币种 | settle.py 增加汇率转换 | 低 |
| 复杂比例分摊 | ExpenseCreate 增加 ratio 字段 | 中 |
| 多人共同付款 | payer 改为 payers[] | 中 |
| 云端同步 | JSON → 数据库 + 用户系统 | 高 |

## MCP = 接什么

### 当前接入

| 系统 | 接口 | 数据 | 权限 |
|------|------|------|------|
| 本地 JSON 文件 | storage.py | 旅行 / 成员 / 账单 / 结算 | 读写 |
| 浏览器 | fetch API | 用户操作 | 只读 |

### 不接入（非目标）

| 系统 | 理由 |
|------|------|
| 微信支付 | PRD 明确不做真实支付 |
| 银行卡 / 支付宝 | 同上 |
| 用户系统 | 不做注册登录 |
| 云存储 | 不做云端同步 |

### 未来可接入

| 系统 | 场景 | 前置条件 |
|------|------|----------|
| 微信小程序 | 移动端入口 | 需企业主体 |
| 数据库（SQLite） | 数据持久化升级 | 数据量增长时 |
| OAuth | 多用户协作 | 需用户系统 |

### 敏感数据隔离

- 无手机号、无真实姓名（成员是虚拟昵称）
- 无支付密钥
- API keys 不入 AI 上下文

## Harness = 自动跑

### 当前流程

```
手动触发：用户操作前端
  ↓
前端 fetch → 后端 API
  ↓
后端处理 → JSON 读写
  ↓
返回结果 → 前端展示
```

### 闭环设计

| 环节 | 自动化 | 失败处理 |
|------|--------|----------|
| 创建旅行 | 前端表单 → POST /trips | 校验拒绝，提示错误 |
| 添加成员 | 前端表单 → POST /members | 校验拒绝，提示错误 |
| 添加账单 | 前端表单 → POST /expenses | 校验拒绝，提示错误 |
| 生成结算 | 前端按钮 → POST /settle | 账单为空提示 |
| 数据持久化 | 后端自动写 JSON | 文件不存在自动创建 |

### 失败 → 人工接管

| 场景 | 自动处理 | 人工接管 |
|------|----------|----------|
| JSON 文件损坏 | 后端返回空列表 | 用户重新录入 |
| 网络断开 | fetch 报错 | 检查后端是否启动 |
| 金额精度异常 | round(v, 2) | 用户手动修改账单 |

### 可扩展的 Harness

| 方向 | 实现 | 价值 |
|------|------|------|
| 定时提醒 | CronCreate 提醒旅行结束前结算 | 防遗忘 |
| 自动备份 | 定时复制 trips.json | 防数据丢失 |
| 结算通知 | 结算完成后推送消息 | 多人同步 |

---

## 与 QA Gates 的关系

- Gates 判定「哪里过关」（Spec / 设计 / 测试 / 代码 / 文档）
- Harness 回答「自动怎么跑」（创建 → 录入 → 结算 → 持久化）
- Gates 挂在 Harness 的每个环节上：创建旅行前检查 Spec，结算前检查账单非空

△ 三者不混：Skill 不管接口调用，MCP 不管执行流程，Harness 不管怎么做

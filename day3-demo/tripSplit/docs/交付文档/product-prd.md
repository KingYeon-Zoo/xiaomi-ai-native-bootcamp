# TripSplit · 旅行 AA 结算助手 PRD

## 用户
旅行参与者（记账人）—— 一人负责录入，旅行结束后把结算结果发到群里

## 目标
把多人旅行的共同支出记录下来，旅行结束后一次性算清楚最终账款分摊

## 非目标
不做用户注册 / 登录
不做云端同步 / 多人实时协作
不做真实支付（微信 / 支付宝）
不做多币种 / 复杂比例分摊 / 多人共同付款
不做移动端适配
不做数据导出（CSV / Excel）
不做 OCR 发票识别
不做长期个人记账 / 预算管理

---

## 核心对象

### 旅行
- 名称（必填）
- 开始日期（必填）
- 结束日期（必填）
- 成员列表
- 账单列表

### 成员
- 名字（必填，不重复，不可编辑，不可删除）

### 账单
- 名称（必填）
- 金额（必填，> 0，保留两位小数，人民币）
- 付款人（必填，1 人，从成员中选）
- 参与人（必填，≥ 1 人，从成员中选，均摊）
- 分类（必填，预设或自定义）
- 日期（默认当天，可修改，不限制在旅行日期范围内）
- 备注（选填）

## 需求与验收

### P0：核心闭环

| ID | 需求 | 验收条件 |
|----|------|----------|
| P0-1 | 创建旅行 | 填写名称 + 开始日期 + 结束日期 → 创建成功，出现在旅行列表 |
| P0-2 | 添加成员 | 输入名字 → 成功添加；名字为空 → 拒绝；名字重复 → 拒绝；至少 2 人才能进入后续流程 |
| P0-3 | 添加账单 | 填写名称 / 金额 / 付款人 / 参与人 → 创建成功；金额 ≤ 0 → 拒绝；参与人为空 → 拒绝 |
| P0-4 | 查看账单列表 | 本次旅行的所有账单按时间倒序展示，显示名称 / 金额 / 付款人 / 参与人 / 分类 / 日期 |
| P0-5 | 结算 | 点击"生成结算" → 展示每人已付 / 应付 / 余额 + 转账方案；所有账单均摊给参与者，算出谁该转给谁；转账次数尽量少 |
| P0-6 | 结算结果展示 | 前端展示结算结果（成员统计 + 转账方案），无复制、无导出 |

| P2-3 | 空状态引导 | 无旅行 / 无成员 / 无账单时展示引导文案，不是空白 |

## 结算规则

1. 遍历所有账单，累计每人"已付金额"和"应付金额"
2. 余额 = 已付 - 应付（正数应收，负数应付）
3. 贪心匹配：每次取最大应收人和最大应付人，转账金额取两者较小值，直到所有人余额归零
4. 目标：转账次数尽量少，总金额对得上
5. 均摊规则：金额 / 参与人数，直接除法，不处理尾差
6. 账单变更（编辑 / 删除）后，旧结算自动作废，需重新生成

## 交互主路径

```
旅行列表 → 创建旅行 → 添加成员（≥2） → 添加账单 → ...持续录入 → 点击结算 → 查看结果
```

## 失败路径

| 场景 | 处理 |
|------|------|
| 金额填 0 或负数 | 校验拒绝，提示"金额必须大于 0" |
| 成员名为空 | 校验拒绝，提示"成员名不能为空" |
| 成员名重复 | 校验拒绝，提示"成员名已存在" |
| 参与人未选 | 校验拒绝，提示"至少选择一个参与人" |
| 结算时账单为空 | 提示"请先添加账单" |

# 提交检查助手 · PRD

## 用户
助教（查提交）、学生（自查）

## 目标
检查提交包缺失项，降低助教成本

## 非目标
不判代码质量 / 不做账号系统
不做云端同步

## 需求与验收
P0 缺 README        → WARNING
P0 缺 AI log        → BLOCKED
P0 损坏 zip         → 可读错误
P1 生成 PASS/WARN/BLOCK 报告
P2 历史记录查询

1 非目标先写死

『不做登录、不做云同步』把范围钉牢，AI 列再多也不越界。

2 每条需求配验收

验收写成可测条件（缺 X→某状态），直接能交给测试。

3 优先级是金字塔

P0 少而硬、P1 增强、P2 可选，绝不是全部 P0。

# 提交检查系统 · 方案取舍

方案    优势        风险        结论
A CLI   最快/最稳   展示弱      备选
B Web   展示强      需后端      选中 ✓
C 小程序 贴近真实   集成高      保留入口

## 最终选择：B Web+服务端
两天可交付 + 集成风险可控

## 为什么不选 A / C
A：答辩展示太弱
C：集成风险高，两天难收口

## 交互主路径
上传 → 检查 → 看结果 → 下报告

## 失败路径
损坏 zip / 超时 → 可读错误兜底

1 三方案要本质不同

CLI/Web/小程序是架构差异，不是换皮，才有比较价值。

2 风险列不能省

每个方案都写失败点，强迫团队提前想兜底，是方案能落地的保证。

3 不选也要给理由

写清为什么不选 A、C，证明选择是判断出来的，不是 AI 推荐的。

# 提交检查系统 · 开发计划
（先让 AI 只出计划，不写代码）

## T1 parseSubmissionZip
入 zip → 出 fileList[ ]
验：解析样例包，断言文件数

## T2 checkEvidenceFiles
入 fileList → 出 missing[ ]
验：缺 README 用例 → missing 含它

## T3 scoreStatus
入 missing → PASS/WARN/BLOCK
验：三状态各一条用例

## T4 renderReport
入 status → HTML/JSON，比对快照

△ 风险：zip 损坏 → T1 兜底返错误

# 提交检查系统 · 测试矩阵

场景            期望        类型
正常提交包        PASS        正常
缺 README        WARNING     边界
缺 AI log        BLOCKED     边界
损坏 zip         可读错误      失败
资料外的问题       拒答        拒答
模型答案无来源      FAIL        来源

## 回归用例
改评分规则后，旧 6 条全跑一遍
断言状态不变 ✓

## 复现说明
每条用例固定输入文件，
失败可稳定重现，不靠运气

1 一半精力在功能之外

拒答、来源、工具异常占 AI 测试的一半，正是传统测试忽略的地方。

2 失败必须可复现

每条用例固定输入，失败能稳定重现，助教才能复核。

3 改动后必跑回归

改了评分规则就把旧用例全跑一遍，确认旧能力没被破坏。

隐藏用例复核 → 进入人工复核

## 准入
含 README+AI log+测试记录才进检查

△ Gate≠Harness：这里判定「哪过关」

====================
1 每个 Gate 有失败动作

不达标就「退回补 X」或「进入复核」，而不是糊弄过去。

2 隐藏用例防作弊

学生看不到的额外样例，防止针对性通过，但要公平合理。

3 别和 Harness 混

Gate 回答「哪里过关」，Harness 回答「自动怎么跑」，是两件事。

# 训练营自动化 · 三件套

## Skill = 怎么做
提交检查流程 + 输出模板
谁来跑都得到一致结果

## MCP = 接什么
接入：题库 / 日程 / 提交系统
权限：学生手机号 不入 AI

## Harness = 自动跑
发现→计时→收包→检查→报告
闭环：失败 → 人工接管

## 与 QA Gates 的关系
Gates 是「哪过关」，挂在 Harness 上

△ 三者不混：Skill 不基接口调用


1 一句话记住分工

Skill=怎么做、MCP=接什么、Harness=自动跑，各管一段才不失控。

2 MCP 必须标权限

接入哪些系统、哪些数据禁止给 AI（如手机号），写得明明白白。

3 Harness 要有闭环

失败能人工接管才算闭环，不是发了题就不管。


一份合格的资料索引：每份资料标用途、版本、适用任务，敏感内容禁止给 AI。

## 敏感隔离规则
- 手机号-脱敏；密钥-永不入 AI

## 按阶段投喂
设计阶段只发 prd + design
问答阶段只发 course-rules 片段

结果：token 降到全量粘贴的 1/5

1 索引让 AI 按需取

标了用途和适用任务，AI 按阶段取片段，不用全量粘贴。

2 敏感数据要隔离

密钥永不入 AI、手机号脱敏，这一列是安全底线。

3 版本号防用错资料

标更新时间，避免 AI 拿到过期资料把结果带偏。

# 可运行原型说明

## 原型目标

LOOPS 原型用于证明四件事：

1. Agent 不是单次提示词，而是规则、专家 Evidence、条件路由、仲裁、策略门和人工复核组成的完整判断链；
2. 传统 ML 路线可以作为低延迟、高吞吐的快速通道保留；
3. 模型只负责结构化取证，确定性策略门掌握自动裁决权限；
4. 冲突、缺失证据或模型失败时，系统会进入可恢复的人工复核状态。

## 运行方式

```bash
./start.sh
```

可选：重新生成本地演示数据。

```bash
cd src/backend
.venv/bin/python seed_demo_data.py
```

打开 <http://127.0.0.1:5173>，默认进入内容审核控制台。

## 演示主路径

1. 在“指标看板”查看 Agent 审核趋势、裁决分布、高风险队列与六阶段流水线。
2. 切换“机器学习方案”，查看固定模型流水线的快速审核定位。
3. 切换“双方案对比”，理解复杂图文走 Agent、稳定低风险流量走 ML 的取舍。
4. 切换 1 小时、24 小时和 7 天范围，确认数据源标签与回退策略。
5. 进入“动态流”提交文本或图片，观察异步 run 状态。
6. 对 `waiting_human` run 通过人工决定接口恢复同一运行。

## 能证明什么

- 前端、服务端与 MongoDB 可以组成一条可运行链路；
- 可信硬规则、快速路径、冲突仲裁和人工恢复均有自动化测试；
- Agent、ML 和对比视图使用同一数据协议；
- 演示现场断开云服务时，页面仍有明确标注的确定性回退数据。

## 不能证明什么

- 看板中的精度、吞吐、成本和聚合数量不是生产实测；
- 当前没有正式标注集，不能据此声称生产准确率；
- 单进程队列、无管理端 RBAC 的实现不适合直接公网部署；
- ML 与 Agent 的统一在线风险路由仍是后续演进项。

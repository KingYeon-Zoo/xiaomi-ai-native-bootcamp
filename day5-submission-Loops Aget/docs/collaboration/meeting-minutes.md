## 同步节点一：项目方向

- 日期：2026-07-17
- 输入：旧项目以机器学习为主，但复杂内容缺少可审计的 Agent 判断链。
- 分歧：直接强化模型指标，还是优先补工具、状态与权限闭环。
- 结论：不推翻 ML 基线；保留快速路线，重构 LLM 为完整 Agent。
- 行动项：完成问题诊断、澄清问题和三条架构路线。
- 负责人：ChinyenZoo。
- 验收与证据：14 个问题、3 个 P0、3 条路线；见 `docs/diagnosis/` 与 `docs/options/`。

## 同步节点二：架构选择

- 日期：2026-07-17
- 输入：需要选择合适的 LangChain 架构。
- 备选：单提示词、全量多 Agent、条件式分层裁决。
- 分歧：全量辩论更直观，但会放大简单内容的成本与故障面。
- 结论：选择方案 C，采用 LangGraph StateGraph 和分层裁决。
- 行动项：实现 fast path、debate path、policy gate 和 HITL，并覆盖路径测试。
- 负责人：ChinyenZoo。
- 验收与证据：`src/backend/app/agents/graph.py`、`test_graph.py`。

## 同步节点三：模型与图片

- 日期：2026-07-17
- 输入：DeepSeek 不支持当前图片需求，豆包模型支持图片。
- 分歧：统一模型可简化配置，但无法保证实际图片能力。
- 结论：DeepSeek 负责文本/critic/arbiter，豆包负责视觉；图片直接送云模型。
- 行动项：增加图片校验、data URL、视觉必要证据和缺失转人工。
- 负责人：ChinyenZoo。
- 验收与证据：`ark.py`、`moderators.py`、`test_ark_agents.py` 与最小云烟测。

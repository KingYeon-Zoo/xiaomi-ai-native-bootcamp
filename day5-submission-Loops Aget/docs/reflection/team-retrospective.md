# 维护者复盘

## 有效做法

- 没有为了“像 Agent”而删除旧 ML，反而用双路线解释性能与深度的真实取舍。
- 把 LLM Evidence 与确定性 Policy Authority 分离，使提示注入、缺模态和模型故障能被测试。
- 把人工复核建模为同一运行的暂停与恢复，而不是独立后台操作。
- 用 Mongo、后端回退和前端回退三层保证演示稳定，同时在界面标明数据源。
- 逆向文档时从代码、测试、Git 和当前命令出发，删除了过期英文叙事和无法复核的强结论。

## 暴露问题

- 旧项目的说明、测试和启动模式同时存在多条历史路线，容易让答辩叙事失焦。
- 双方案“能力”已经存在，但统一 ML→Agent 在线风险路由还没有接通。
- 旧 ML 全量依赖重，轻量 Agent 环境无法顺便完成全部模型回归。
- 单进程队列、无管理鉴权和无标注集意味着当前只能是演示 MVP。
- 过程证据没有始终随代码同步保存，后期恢复判断链的成本偏高。

## 后续改进

1. 建立一个统一审核入口，先跑轻量特征，再按风险升级 Agent。
2. 引入外部队列、幂等键、任务租约和多实例恢复。
3. 建立标注回放集，分开测 ML、Agent 和混合路由的质量、成本、延迟。
4. 为 trace 和人工操作增加 RBAC 与审计日志。
5. 前端路由级拆包，降低图表和动画对首屏的影响。
6. 从项目开始就同步保存任务、决策、Review 与运行证据。

本复盘依据当前仓库、提交与实际运行结果整理。

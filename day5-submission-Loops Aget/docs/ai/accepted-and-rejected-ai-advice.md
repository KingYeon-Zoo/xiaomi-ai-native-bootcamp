# AI 建议的接受、拒绝与修改

| 状态 | AI 建议 | 人工判断 | 最终影响 |
|---|---|---|---|
| 接受 | 使用 LangGraph 自定义 StateGraph | 条件路由、并行、checkpoint、HITL 与现有 FastAPI/Mongo 匹配 | 成为 Agent 编排核心 |
| 接受 | 文本 DeepSeek、视觉豆包 | 用户已确认图片必须真实审查，DeepSeek 不承担视觉职责 | 分成文本与视觉 Evidence |
| 接受 | LLM 只产证据，确定性策略门裁决 | 可防提示注入和模型自提权 | 增加可信来源和必要证据校验 |
| 修改 | 所有高风险内容都进入完整辩论 | 全量调用成本和时延过高 | 仅冲突、低置信、高风险或不可用时触发 critic/arbiter |
| 修改 | 立即交付完整 ML→Agent 混合路由 | 当前代码已具备双能力，但统一在线路由尚未实现 | 先交付双方案与看板，把统一路由列为下一步 |
| 修改 | 所有结构化响应都强制 JSON Schema | 部分方舟模型明确不支持该格式 | 仅遇到明确格式错误时降级 JSON 对象，仍做 Pydantic 校验 |
| 拒绝 | 让 LLM 输出 `HARD_BLOCK_*` 就直接拦截 | 不可信模型不能提升自身权限 | 只信 `rule/attack_tool` 来源 |
| 拒绝 | 把旧云烟测和旧指标直接写进提交结果 | 缺少本轮日志，演示值也不是实测 | 重新执行最小云烟测，演示数据单独标注 |
| 拒绝 | 用 AI 同步记录冒充多人会议 | AI 不是项目成员，也没有真实参与者证据 | 协作文档只记录可核验的人机同步 |
| 拒绝 | 沿用本地工具过程缓存 | 缓存不属于产品证据，且可能含本地状态 | 从开源仓库与证据链排除 |

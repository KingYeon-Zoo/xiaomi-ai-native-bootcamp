# 澄清问题

| 优先级 | 问题 | 当前结论 | 若答案不同，方案如何变化 |
|---|---|---|---|
| P0 | 项目首先优化模型效果，还是可审计的 Agent 判断链？ | 以 Agent 判断链为主，ML 作为第二方案保留 | 若以模型效果为主，应把时间投入标注集、训练和离线评测 |
| P0 | 图片必须由真实多模态模型审查吗？ | 必须；视觉职责交给豆包多模态 | 若不要求图片，可删除视觉 Agent 与缺模态策略 |
| P0 | 谁拥有最终自动裁决权？ | 确定性策略门；LLM 只提供证据与建议 | 若由 LLM 全权决定，代码更少但提示注入和越权风险更高 |
| P1 | 简单内容是否也要多轮辩论？ | 不需要，按风险条件触发 critic/arbiter | 若全部辩论，演示更“Agent 化”但时延、成本和故障面增加 |
| P1 | 文本与图片是否使用同一个模型？ | DeepSeek 负责文本类角色，豆包负责视觉 | 同一多模态模型可简化配置，但降低专家分工和故障隔离 |
| P1 | 发帖接口同步等待还是异步返回？ | 异步返回 run ID，前端轮询 | 同步更简单，但无法自然承载长调用和人工暂停 |
| P1 | 人工复核是新任务还是恢复原任务？ | 恢复同一 `run_id/thread_id` | 新任务会切断证据、检查点和审计链 |
| P1 | 前端重点展示模型指标还是审核运营？ | 默认展示 Agent 运营，看板可切换 ML 与对比 | 若只展示模型指标，会弱化运行状态与人工复核链路 |
| P1 | 演示数据是否必须来自实时云调用？ | 可用确定性 Mongo 快照，必须显式标注 | 若要求实时云数据，需要稳定配额、回放集和防抖缓存 |
| P2 | 旧 ML 代码是否删除？ | 不删除，作为高速路线和历史资产 | 删除可减小体积，但失去双方案取舍基础 |
| P2 | 是否保留 Ollama 路线？ | 代码历史资产保留，但不作为当前主讲路线 | 若纳入主线，需要重新验证模型、资源和图片能力 |
| P2 | 是否需要多实例部署？ | 当前不需要，单进程演示 | 若需要，必须引入外部队列、租约、幂等和分布式 checkpoint |
| P2 | Trace 是否对普通用户开放？ | 普通状态接口隐藏 trace，管理接口单独提供 | 若公开，需重新做隐私、提示泄露和授权审查 |
| P2 | 阈值和政策由谁维护？ | 当前是工程初值，责任人未记录 | 上线前需政策版本、灰度、回滚与责任人 |

前三个 P0 分别决定项目重心、是否需要视觉分支，以及 LLM 与策略的权限边界，都会改变总体架构。

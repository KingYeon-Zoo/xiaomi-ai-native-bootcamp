# 被拒与被修改的方案

## 拒绝仅优化提示词

单次提示词不能证明工具、状态、条件路由、故障恢复与人工闭环，也无法限制模型自提权，因此不作为主方案。

## 拒绝 LLM 直接拥有硬拦截权

用户内容可能包含提示注入，模型输出也可能伪造政策代码。当前策略同时校验代码前缀和 Evidence 来源，只有本地受信工具可触发硬规则。

## 拒绝 DeepSeek 负责图片取证

已确认的模型能力边界是 DeepSeek 负责文本类角色、豆包多模态负责图片。视觉 Agent 因此独立配置。

## 修改“所有内容都进入多 Agent”

全量 critic/arbiter 会让简单内容也承担额外调用。本项目改为条件升级：冲突、低置信、高风险或 Agent 不可用才进入复核链。

## 修改“立即实现完整混合路由”

双路线的业务建议成立，但当前代码入口仍以配置选择 Agent 或旧服务，尚未实现生产级统一路由。为避免把设计写成实现，本轮先完成双方案看板和边界说明，统一调度列为下一步。

## 拒绝把本地工具缓存当作项目证据

本地 AI 工具缓存既不属于产品源码，也无法替代可运行测试、提交和人工判断，因此不进入开源仓库或验收证据链。
